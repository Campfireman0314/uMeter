# uMeter v2.5.0 Release Notes

Prepared: 2026-11-13

v2.5.0 packages the current WPF desktop app, native DSP accelerator, and VST3 Sender. It combines the metering/performance/accessibility optimization passes with the About/credits and Signal Shuffle work developed since v2.4.0.

## Metering and Performance

- K-weighting follows the source sample rate while preserving the established 48 kHz calibration. Independent-reference fixtures cover 44.1/48/96 kHz; analytical true-peak and streaming/reset fixtures strengthen numerical regression coverage.
- Sliding power/peak windows use fixed-capacity storage. Stereo point sampling avoids transient collection work, and published waveform/spectrum snapshots remain immutable.
- Integrated loudness caches results between completed blocks and queries an exact-power aggregate index instead of scanning the full history after every completed block. Threshold membership remains strict, without quantization or history truncation. Indexed sum order can differ within the documented 1e-10 LU numerical comparison budget; bit-identical integrated results are not promised.
- Existing graph resolution/cadence and native/managed fallback are retained. Transport and plugin audio processing are unchanged by the optimization passes.

### Measured Scope and Memory Tradeoffs

Previously recorded follow-up measurements compare `35f713f` with the optimized implementation, using the same native DLL/harness, 48 kHz stereo, 4x true peak, 480-frame blocks, fresh processes, three warmups, and three repeats. These are not new measurements of the version-only release bump.

| Synthetic scenario | Processing time | Cumulative managed allocations |
| --- | --- | --- |
| 60 s Normal | 1043.4 to 923.8 ms (-11.5%) | 37,319,520 to 27,855,784 B (-25.4%) |
| 300 s Normal | 5043.3 to 4839.4 ms (-4.0%) | 127,809,520 to 116,796,512 B (-8.6%) |
| 3 sources with channel graphs, Normal | 977.4 to 945.8 ms (-3.2%) | -39.1% |
| 3 sources with channel graphs, Eco | 501.2 to 459.7 ms (-8.3%) | -51.9% |

The isolated 30,000-block gate benchmark improved from 566.9 to 22.0 ms (25.8x for that workload), but retained memory increased from 262,456 to 1,216,592 B. Production index retention is O(distinct measured powers), not bounded-session memory: approximately 72 B/node on x64 .NET, or about 2.59 MB/hour per gate at 10 mostly-distinct blocks/s, excluding other storage. Overall/Mid/Side have separate gates.

Raw spectrum history replaces the old row-level history rather than adding another full history. Representative retention increases by 286 KiB per control; maximum raw level storage is 1,228,800 B per control, with pixel/other storage additional.

These single-machine synthetic measurements are not whole-app CPU, end-to-end latency, retained-RAM savings, or portable performance guarantees. Full protocol, repeat scatter, numerical observations, and limitations: [`performance follow-up verification`](../openspec/changes/performance-followup-spectrum-level/test-report.md).

## Spectrum Cursor and Accessibility

- Spectrum hover labels show frequency plus one-decimal dBFS, for example `1 kHz · -24.3 dBFS`, from the nearest retained raw source bucket at the hovered historical column. Values do not come from color, a stronger neighboring rendered-row bucket, or the newest spectrum.
- Unavailable data shows `—`; stored floor/ceiling states show `≤ -200 dBFS` / `≥ 0 dBFS`. This is an FFT-bucket estimate, not an arbitrary-frequency calibration, true-peak, or RMS measurement. The pre-existing low-sample-rate frequency-display approximation is unchanged.
- Inline, popup, and channel controls share the behavior. Pointer movement does not run FFT/audio processing. History wrapping, partial alignment, pan/zoom mapping, DPI-snapped seams, reset/source-size changes, and color invariance have automated coverage.
- Core sliders support keyboard adjustment and numeric editing, themed focus feedback, localized accessible names, and UI Automation value/range providers. Endpoint focus and dynamic/fractional bounds have regression coverage.

## Other Changes Included Since v2.4.0

- Global Settings includes About/version/credits and a project-repository action.
- Signal Shuffle adds the localized layered tile game, a selectable audio-source feed, deterministic solvable boards, tools, and beat-reactive sheep/visual feedback. See the v2.5.0 changelog for the detailed game changes.
- Sender-triggered startup avoids relaunching an already-running resolved host in the current Windows session. The game audio-source selector uses source names/aliases.
- Existing localization, startup controls, source persistence, and sender transport behavior remain available.

## Remaining Acceptance and Limitations

- Real Narrator traversal/announcements, Windows high-contrast, language/theme switching, narrow-label readability, and 100/150/200% or mixed-DPI appearance remain unverified by a human.
- Live multi-source WASAPI/DAW checks at 44.1/48/96 kHz, including collision and Signal Shuffle consumers, remain open. The user's positive feedback is not a substitute for specific observed acceptance evidence.
- Independent-reference and analytical fixtures do not establish ITU/EBU certification or full official programme-material validation.
- The installer remains unsigned; Windows SmartScreen may warn. No signing credentials or global configuration are changed.
